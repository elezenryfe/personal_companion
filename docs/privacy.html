Privacy Policy

Effective date: 7 November 2026

This policy explains how the Ryfe Windows desktop application handles information when you configure and use its integrations. Ryfe is an open-source project maintained by its developer. The application runs on your Windows computer; its connected services communicate with their respective providers over the internet.

In short: Ryfe stores configured credentials in the Windows credential store. When you use an integration, the relevant information is sent to that service (for example, Google, GitHub, or DeepSeek) to perform the requested feature. Do not connect accounts or enter information unless you are comfortable with those services receiving the data needed for the feature.

1. Information Ryfe handles

  • Account credentials and tokens: API keys, OAuth client credentials, and OAuth refresh tokens that you enter or obtain when connecting services. The application stores secrets using the Windows credential store rather than ordinary application settings.
  • Local development information: When you use repository features, Ryfe reads information from the local Git repositories and files you select, such as repository status, branch names, changed-file information, and diffs.
  • GitHub information: When configured, Ryfe communicates with GitHub to retrieve the pull-request and contribution information shown in the app.
  • Gmail information: When you connect Gmail, Ryfe requests the gmail.modify permission. Its inbox feature retrieves your account email address, unread count, and up to 12 inbox message records. The message records include sender, subject, snippet, date, and unread status; the current inbox implementation requests message metadata rather than full message bodies.
  • AI conversations: Prompts and context used by the assistant may be sent to DeepSeek's API for processing. Context can include information from your repositories or files when the assistant uses the corresponding tools.

2. How Gmail access is used

Ryfe uses Google's OAuth 2.0 flow with PKCE and a local loopback callback on your computer. Gmail access is used to display inbox information and to perform the actions exposed in the app: archive a message, mark a message as read, and create a Gmail draft. The current Gmail module does not implement sending an email.

When you create a draft, the draft content is sent to Google's Gmail API so Google can save it in your Gmail account. Gmail access tokens are used to call Google's API. Ryfe stores the refresh token locally in the Windows credential store so it can obtain new access tokens when needed.

You can disconnect Gmail from within Ryfe. You can also revoke Ryfe's access from your Google Account's third-party connections page. Disconnecting in Ryfe removes the locally stored refresh token; revoking access with Google is the separate way to withdraw the app's Google authorisation.

3. Where information goes

  • Google: Receives OAuth requests and Gmail API requests needed to connect and use Gmail.
  • GitHub: Receives requests for the GitHub features you configure and use.
  • DeepSeek: Receives assistant prompts and any contextual information included in requests to its API.

These services process information under their own privacy policies and terms. Ryfe does not control their independent handling, retention, or processing of information. Review the providers' policies before enabling their integrations.

4. Storage and security

Ryfe is designed to keep API keys and OAuth tokens in the Windows credential store. The application settings file is used for ordinary preferences, not as the intended store for secrets. No software can guarantee absolute security; keep Windows and Ryfe up to date, protect your Windows account, and do not share your credentials.

5. Data retention and deletion

Credentials remain in the Windows credential store until you remove them through Ryfe's settings or disconnect the relevant integration, or remove them using Windows credential-management tools. Local repository files remain wherever you store them; Ryfe does not own or control those files. Information already sent to Google, GitHub, or DeepSeek is subject to that provider's retention and deletion controls and policies.

6. Analytics and advertising

This project does not describe an in-app advertising or analytics feature. The hosting provider for this website (GitHub Pages) and the external service providers you use may process technical information, such as request data, under their own policies.

7. Children's privacy

Ryfe is a general-purpose developer productivity application and is not designed for children.

8. Changes to this policy

This policy may be updated when Ryfe's features or data practices change. The effective date at the top indicates the latest revision. Check this page and the public source repository for updates.

9. Contact

For questions or privacy requests about Ryfe, open an issue in the Ryfe GitHub repository. Please do not post passwords, API keys, OAuth secrets, refresh tokens, or private email content in a public issue.
